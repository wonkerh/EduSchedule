Technology

Your full tech stack.

Framework
React Native + Expo
One codebase. Runs on your iPhone via Expo Go instantly. No Mac, no Apple developer account needed.
Storage
AsyncStorage + SQLite
AsyncStorage for settings and preferences. expo-sqlite for all timetable and event data.
Navigation
React Navigation
Bottom tab navigator for the 5 screens. Stack navigator inside each tab for sub-pages.
Notifications
Expo Notifications
Schedule local push notifications for class reminders and study sessions. Works offline.
Calendar UI
react-native-calendars
Ready-made calendar component. Mark events, tap days, monthly view — all built in.
IDE
VS Code
With React Native Tools and Prettier extensions. Expo runs directly in the VS Code terminal.
Build plan

6 weeks.
Step by step.

01
Setup & skeleton
Week 1 — get everything running
Install all tools once only
Node.js (LTS) from nodejs.org — the engine that runs JavaScript
VS Code from code.visualstudio.com — your IDE
Expo Go from the App Store on your iPhone
VS Code extensions: React Native Tools, Prettier, ES7+ Snippets
Create the Expo project React Native
Open VS Code terminal and run: npx create-expo-app TimetableApp
cd TimetableApp then npx expo start
Open Expo Go on your iPhone and scan the QR code — your app is live
You should see the default Expo welcome screen on your phone
Set up folder structure organisation
/screens — one file per screen: Dashboard.js, Timetable.js, Calendar.js, Reminders.js, Settings.js
/components — reusable pieces: ClassCard.js, EventBadge.js, ReminderItem.js
/data — database setup and query functions
/utils — helper functions like formatTime(), getDayName()
Build bottom tab navigation React Navigation
Install: npm install @react-navigation/native @react-navigation/bottom-tabs
Install required deps: npx expo install react-native-screens react-native-safe-area-context
Wire all 5 screens into a bottom tab bar with icons
Goal for week 1: tap between all 5 screens, each shows just its name as placeholder text
02
Data layer
Week 2 — database and storage
Set up SQLite database expo-sqlite
Install: npx expo install expo-sqlite
Create table: Classes (id, subject, day, startTime, endTime, room, colour)
Create table: Events (id, title, date, type: school|personal, notes)
Create table: StudySessions (id, subject, scheduledTime, duration)
Write helper functions: addClass(), getClasses(), deleteClass(), addEvent()
AsyncStorage for settings AsyncStorage
Install: npx expo install @react-native-async-storage/async-storage
Store: userName, theme (light/dark), semesterStartDate, notificationsEnabled
Create a useSettings() custom hook to read and write these values cleanly
Test by saving a name in Settings and reading it back on the Dashboard
03
Build each screen
Weeks 3–5 — the real building
Timetable screen — build this first start here
Build a weekly grid: columns = Mon–Fri, rows = time slots (8am–8pm)
Render a coloured block for each class loaded from the database
Add a floating + button that opens an Add Class form (subject, day, time, room, colour)
Tap a class block to view details or delete it
Build this first — Dashboard and Reminders depend on this data
Dashboard screen second
Greeting card: "Good morning, Mziwonke" — pulls name from AsyncStorage
Ongoing class card: checks current time against today's classes
Upcoming classes list: next 3 classes today from the timetable data
Events strip: today's school and personal events from the Events table
Study reminder banner: shows if a study session is scheduled within 1 hour
Calendar screen third
Install: npm install react-native-calendars
Mark dates that have events using the markedDates prop
Tap a date to show an agenda list below the calendar
Add Event button: form with title, date, type (school or personal), notes
Use different dot colours for school events vs personal events
Reminders screen fourth
Install: npx expo install expo-notifications
Request notification permission on first open using Notifications.requestPermissionsAsync()
List all classes with a toggle switch to enable/disable reminder for each one
Default reminder fires 15 minutes before class starts
Add Study Session: pick subject, date, time, duration — schedules a local notification
Settings screen fifth
Name input — saved to AsyncStorage, shown in the Dashboard greeting
Theme toggle (light/dark) — store preference, apply a ThemeContext app-wide
Semester start date picker
Notifications global on/off toggle
Clear all data button — always show a confirmation alert before deleting
04
Polish & ship
Week 6 — finish and publish
Dark mode theming polish
Create a ThemeContext using React's Context API
Define a lightTheme and darkTheme object with all your app colours
Every component reads colours from the theme — no hardcoded hex values
Settings toggle flips the context — whole app updates in real time
Test on your iPhone with real data testing
Add your actual UKZN timetable — real subjects, real times, real rooms
Check every screen on your phone screen size
Test that notifications actually fire at the right time
Fix any layout issues — safe area insets, keyboard behaviour, scroll views
Push to GitHub publish
Create a new repo: TimetableApp on your wonkerh GitHub account
Add a .gitignore to exclude node_modules
Write a README: what the app does, what you learned, tech stack used
Add screenshots of your real app running on your iPhone
This is Project 02 on your roadmap — done, live, and visible to the world

Developer mindset

Things to remember
as you build.

01
Build Timetable before Dashboard
The Dashboard needs real class data to show anything useful. If you build it first you'll stare at an empty screen with nothing to test. Data first, UI second.
02
Commit to GitHub every day
Even if you only changed 10 lines. A history of daily commits is proof of a developer who shows up. It matters more than any grade.
03
Use your own real data
Add your actual UKZN timetable. Real data breaks things in real ways. Testing with dummy data hides half your bugs.
04
One screen at a time
Don't start screen 3 until screen 2 fully works. Jumping between unfinished screens leads to a messy codebase and nothing that actually works.
05
Break things. Fix them.
The error messages are the lessons. Don't copy a fix without reading it first. Understanding why something broke is worth more than the fix itself.
06
This app is your hello world
Every great developer remembers their first real app. Six weeks from now you'll use this every day. That's what makes it real — not the code, but what it does for you.
